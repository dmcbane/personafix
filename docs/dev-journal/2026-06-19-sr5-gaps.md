# SR5 Remaining Gaps — 2026-06-19

## Context

SR5 character creation is functional end-to-end as of v0.25.0: the priority table
works, attribute/skill budgets display and validate, magic validation fires, nuyen
budget enforces correctly. Spot-check confirmed on this date.

---

## Known gaps (all tracked in backlog P6-*)

### P6-1 — Panel layout consistency

The Skills panel has a good UX pattern: filters top, search, drop-down + Add button,
then the list of selected items at the bottom. The other data panels (Qualities, Augs,
Gear, Magic) were built independently and have slightly different layouts. User confirmed
the Skills design is the target; the other four panels need to be brought into alignment.
Contacts is intentional exception: add form stays at top, existing contacts below.

### P6-2 — SR5 Awakened subtype not enforced

The `magic_or_resonance` priority level description says "Magician (6)", "Adept (6)",
"Mystic Adept (6)", "Technomancer (5)" etc., but the code only checks whether magic is
null or not and whether it exceeds the priority max. The *type* of Awakened character
(Magician / Adept / Mystic Adept / Technomancer) is not stored or enforced.

Impact:
- An Adept can add spells (should be restricted to adept powers only)
- A Magician sees no adept powers panel (should see spells only)
- Technomancers cannot add complex forms at all

Fix: add a `awakened_type: Option<AwakenedType>` field to CharacterDraft (or derive it
from the priority description string), gate the MagicPanel content on it.

### P6-3 — SR5 special attribute pool not tracked

Metatype priority A/B/C gives 13/11/9 special attribute points. These are used to raise
Magic or Resonance above the starting value, or Edge above racial minimum. Currently the
UI hard-sets Magic to the priority starting value; the player cannot raise it further
within character creation (only via career karma).

This is the mechanism by which a priority-A Magician reaches Magic 6 (they start at 6
from priority — but a B-priority Magician only starts at 3 and uses special points to
raise it). The pool also covers subrace cost for non-Human metatypes.

Fix: track `special_attr_points_used: u8` on the draft, show pool in AttributePanel,
allow Magic/Resonance/Edge raises that draw from the pool.

### P6-4 — SR5 contacts use free pool (Cha × 3), not karma-per-point

In SR5 at creation, contacts are free up to `Charisma × 3` total connection+loyalty
points. Beyond that cap, each extra point costs 1 karma. The current implementation
charges 1 karma per point unconditionally (lifted from the SR4 BP model). The
ContactPanel therefore over-charges SR5 characters.

Fix: compute `free_pool = charisma × 3`, show `used / free_pool` in ContactPanel,
flag excess as karma cost, validate in SR5Rules::validate_creation.

### P6-5 — SR5 adept powers panel missing

The MagicPanel shows spells only. Adepts spend power points (equal to Magic rating) on
adept powers, not spells. No adept powers exist in the current UI; an adept character
has nothing useful in the Magic tab.

Fix: load `adept_powers` from game_data.db; show powers panel for Adept/Mystic Adept
awakened types; track power point pool = Magic rating − points spent.

## Non-blocking notes

- The `priority_selection` in PriorityPanel is fully functional and clean — no changes
  needed there.
- SR5 qualities are in game_data.db and load correctly via `get_qualities(edition=SR5)`.
- SR5 conflict detection (essence overage, magic+resonance, attribute/skill overbudget)
  all fire correctly.
- Career play (P5 features) is edition-agnostic and works identically for SR5 characters.
